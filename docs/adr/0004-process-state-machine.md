# ADR-0004: Форма опису процесу оплати - машина станів

## Контекст та проблема
ЛР №4 вимагає описати один процес однією точною формою. Процес оплати керується статусами `Booking`, `FlightSeat`, `Payment` з ЛР №1, а ЛР №3 уже описує обмін повідомленнями (sequence).



## Розглянуті альтернативи
1. **Activity.** (+) Зручна для потоку дій. (-) Статуси неявні, повноту переходів перевіряти довше.
2. **BPMN.** (+) Ролі й message flow видно одразу. (-) XML непростий для читання, частково дублює Sequence з минулої ЛР.
3. **Машина станів (обрано).** (+) Стани будуть мапітиться на статуси БД, повноту видно в таблиці переходів. (-) Ролі показані в підписах, а не у swimlanes.

## Рішення
Mermaid `stateDiagram-v2`. Повідомлення подаємо як підписи переходів "відправник -> отримувач - повідомлення".

## Наслідки
Повноту й досяжність можна перевірити таблицею. Зв'язок зі схемою БД прямий.
