# ADR 4: Моделювання життєвого циклу замовлення через машину станів

## Контекст і постановка проблеми
Для забезпечення цілісності даних у системі необхідно формалізувати дозволені переходи станів замовлення `Booking.status` та виключити невалідні зміни статусів (наприклад, перехід із `CANCELLED` у `PAID`).

## Розглянуті альтернативи
1. **Альтернатива 1 (Activity Diagram)**: моделювання процесу як послідовності дій користувача та системи.
2. **Альтернатива 2 (State Machine Diagram - stateDiagram-v2)**: моделювання життєвого циклу сутності `Booking` із фіксацією подій, умов та паралельних підстанів.

## Рішення
Обрано **Альтернативу 2**.  
Машина станів напряму відображає поле `Booking.status` у базі даних з ЛР №1 та гарантує відсутність досяжності невалідних станів.

## Наслідки
* **Позитивні**:
  * Пряма відповідність enums у базі даних (`PENDING`, `PAID`, `CANCELLED`).
  * Явна фіксація правил холдування та скасування за таймаутом.
* **Негативні**:
  * Потреба у використанні складених та паралельних станів для відображення фонових процесів.
